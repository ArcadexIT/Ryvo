Ryvo

Ride, bid, and parcel marketplace. This file is the installation and user guide for the customer app, the driver app, the API, and the admin panel.

Open this page in any browser. It does not need a server. Work from top to bottom the first time. After the server is up, use the configure sections for Maps, Firebase, Stripe, and the mobile builds.

Before you go live. Every key in this download is the placeholder xxxxxxxx. Search the project for xxxxxxxx and replace each one with your own value: API URL, Maps, Stripe, Firebase, and database password. The project still builds with those placeholders. Change the admin password, and change the Android application id and iOS bundle id before the first store upload. The demo OTP 123456 works only when the API is not in production mode.

Introduction

Ryvo is one product in four parts:

FolderWhat it is
ryvo-customerFlutter app for riders. Android and iOS.
ryvo-driverFlutter app for drivers. Android and iOS.
ryvo-adminNestJS API, Next.js admin panel, Prisma database.
scriptsPoints both mobile apps at your API.

Riders book a ride, offer a bid, or send a parcel. Drivers go online, accept the job, and get paid. Staff run the city from the admin panel: verification, dispatch, fares, wallets, and payouts. The same API serves the apps, the panel, and optional WhatsApp booking.

Features

Customer app

  • Phone and password sign-in, registration, and password reset.
  • Ride, bid, and parcel on one map.
  • Fare shown before the rider confirms.
  • Live driver tracking, in-trip chat, and trip sharing.
  • Card (Stripe), wallet, and cash, each of which you can turn on or off.
  • Saved places, invoices, support tickets, ratings, and account deletion.

Driver app

  • Online and offline. Nearby requests show pickup, drop-off, and earning.
  • Accept or decline, mark arrival, run the trip, complete it.
  • Identity, licence, vehicle, and insurance upload. Riders only see approved drivers.
  • Earnings, bank account, Stripe payouts, and daily, weekly, or monthly plans.
  • Trip chat, support tickets, and account deletion.

Admin panel

  • Overview, live map, dispatch board, and trip detail.
  • Riders, drivers, document verification, and reviews.
  • Payments, wallets, earnings, payouts, and invoices.
  • Ride types, fare rules, promo codes, and driver plans.
  • Support tickets, broadcasts, banners, FAQs, and legal pages.
  • Currency, commission or subscription, surge, countries, staff roles, and audit log.

Accounts you create

Ryvo does not include these services. You create each account and paste your own keys.

  • Google Cloud, for Maps SDK on Android, Maps SDK on iOS, Places, and Maps JavaScript.
  • Firebase, for Cloud Messaging. One project, two apps (customer and driver).

Server installation

Use this on a fresh Ubuntu server. It is the path most buyers should follow. Local installation is the next section, for development on your own computer.

  1. Point your domain’s A record at the server IP. Wait until it resolves.
  2. SSH in as a user who can run sudo.
  3. Install git if it is not there: sudo apt-get update && sudo apt-get install -y git curl
  4. Upload this project and enter the folder: 
    cd /opt
sudo mkdir -p ryvo && sudo chown "$USER" ryvo
# copy the project here, then:
cd /opt/ryvo
  5. Run the installer: 
    bash ryvo-admin/docker/install.sh
  6. Answer the prompts. Press Enter to accept a default. Leave a payment or SMS field empty if you will add it later in the admin panel.
    PromptWhat to enter
    Public domainexample.com with no https:// and no path. Use localhost only for a private test.
    Admin phoneYour phone in international form, such as +447700900000. This becomes the admin login.
    Google Maps API keyA browser key with Maps JavaScript API enabled. Used by the live map.
    Stripe secret and publishable keysBoth from the same Stripe account, both test or both live.
    TwilioAccount SID, auth token, and the SMS from-number or Messaging Service SID.
    WhatsApp from-numberOptional. Leave empty to skip.
    OpenAI keyOptional. Leave empty to use keyword booking.
    Postgres passwordAccept the generated password unless you have a reason to type one.
  7. Wait. The first build compiles the API and the admin panel. On a 2 GB server this can take several minutes. The script then waits until http://127.0.0.1:4180/api/v1/health returns, and creates the admin user.
Where the site actually listens. Docker binds to 127.0.0.1:4180 on the server. It does not open ports 80 or 443 by itself. The next section publishes it with HTTPS. Until you do that, the panel is only reachable on the server itself.

If the script stops with “The API did not become healthy”, read the log and run the installer again:

docker compose -f ryvo-admin/docker/docker-compose.prod.yml logs --tail=80 api

Run install.sh once on a new server. Running it again rewrites apps/api/.env.production. If an admin user already exists, the second run does not change that password.

Public HTTPS

Install Nginx on the host and proxy every request to port 4180. The sample file is ryvo-admin/docker/host-nginx.conf.example.

  1. sudo apt-get install -y nginx certbot python3-certbot-nginx
  2. Copy the sample, replace example.com with your domain, and enable the site: 
    sudo cp ryvo-admin/docker/host-nginx.conf.example /etc/nginx/sites-available/ryvo
sudo sed -i 's/example.com/your-domain.com/' /etc/nginx/sites-available/ryvo
sudo ln -sf /etc/nginx/sites-available/ryvo /etc/nginx/sites-enabled/ryvo
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
  3. Issue the certificate: sudo certbot --nginx -d your-domain.com
  4. Open https://your-domain.com. You should see the admin login.
  5. Open https://your-domain.com/api/v1/health. You should see "status":"ok".

Nginx must forward the Upgrade and Connection headers. The sample file already does. Without them the live map and trip tracking stay disconnected.

API base URL for the apps: https://your-domain.com/api/v1

Socket URL for the apps: https://your-domain.com

Local installation

Use this when you want to change the code on your computer. Production servers should use the installer above.

  1. Install Node.js 20+, Docker, and Flutter.
  2. Start Postgres and Redis: 
    cd ryvo-admin/docker
docker compose up -d
    Postgres is published on port 5433, so it does not collide with a Postgres you already have on 5432.
  3. Install JavaScript dependencies from ryvo-admin: 
    cd ../
npm install
  4. Copy the env templates and leave the local defaults for a first run: 
    cp packages/database/.env.example packages/database/.env
cp apps/api/.env.example apps/api/.env
cp apps/admin/.env.example apps/admin/.env
  5. Create the database and the demo accounts: 
    npm run db:generate
npm run db:push
npm run db:seed
  6. Start the API and the admin panel in two terminals: 
    npm run dev --workspace=@ryvo/api
npm run dev --workspace=@ryvo/admin
URLPurpose
http://localhost:3000Admin panel
http://localhost:4000/api/docsSwagger
http://localhost:4000/api/v1/healthHealth check

For a phone on the same Wi-Fi, the API URL cannot be localhost. Use the computer’s LAN IP. The Android emulator uses http://10.0.2.2:4000/api/v1.

First login

Server

Phone: the number you typed into the installer. Password: 123456. Sign in at https://your-domain.com, then change the password from the admin profile before you share the URL.

Settings you should set first

  1. General. Choose the currency. Set matching radius and offer timeout for your city. Choose commission or subscription. Commission takes a percentage of each fare. Subscription charges drivers for a plan and can take no commission.
  2. Billing. Turn on the payment methods you actually offer: card, wallet, cash. Paste the Stripe publishable key and secret from the same account. Set cancellation fees, or leave them at 0.
  3. Integrations. Paste the Google Maps browser key so the live map loads.
  4. Notifications. Leave driver registration OTP on when Twilio is configured. Turn it off only for a closed test where you accept the development code.

A new driver stays unverified until someone opens Verification and approves the documents. Until then that driver cannot take trips.

Google Maps

Create a key in Google Cloud and restrict it. You need more than one restriction because the admin site, Android, and iOS do not share a key style.

  1. Enable Maps JavaScript API, Maps SDK for Android, Maps SDK for iOS, Places API, and Geocoding API.
  2. Browser key, restricted to your admin domain. Paste it in Admin → Settings → Integrations, and into NEXT_PUBLIC_MAP_API_KEY if you build the admin image yourself. The installer asks for this key and passes it into the admin container.
  3. Android key, restricted by package name and SHA-1. Put it in both apps:
    • ryvo-customer/android/app/src/main/AndroidManifest.xml meta-data com.google.android.geo.API_KEY
    • ryvo-driver/android/app/src/main/AndroidManifest.xml the same meta-data
  4. iOS key. Put it in GMSApiKey inside each app’s ios/Runner/Info.plist.
  5. The apps also read MAPS_API_KEY from scripts/whitelabel.env at build time. Use that for the Dart fallback so you do not have to edit source for every build. The manifest and Info.plist values are still required for the native map.

Billing must be enabled on the Google Cloud project or the map tiles stay blank.

Firebase push

Push uses Firebase Cloud Messaging. Create one Firebase project and add two Android apps and two iOS apps.

AppAndroid packageiOS bundle
CustomerThe applicationId in ryvo-customer/android/app/build.gradle.ktsThe bundle id in the customer Xcode target
DriverThe applicationId in ryvo-driver/android/app/build.gradle.ktsThe bundle id in the driver Xcode target

Change those ids to your own before you create the Firebase apps. The ids shipped in the project may already belong to another Play listing. See App name and IDs.

  1. Install the FlutterFire CLI: dart pub global activate flutterfire_cli
  2. From ryvo-customer run flutterfire configure and select the customer apps. This writes lib/firebase_options.dart, android/app/google-services.json, and ios/Runner/GoogleService-Info.plist.
  3. Repeat from ryvo-driver for the driver apps.
  4. In Firebase, open Project settings → Service accounts → Generate new private key.
  5. Save that JSON as ryvo-admin/apps/api/firebase-service-account.json on the server.
  6. Rebuild the API container so it mounts the file: 
    bash ryvo-admin/docker/redeploy.sh
    On a server that was not cloned with git, rebuild with: 
    docker compose -f ryvo-admin/docker/docker-compose.prod.yml up -d --build api

Without the service account, the apps still run. Push notifications do not.

Stripe

  1. In the Stripe Dashboard, copy the publishable key and the secret key. Use test keys until a real card payment succeeds.
  2. Server installer: paste both when asked. Or later, put the secret in ryvo-admin/apps/api/.env.production as STRIPE_SECRET_KEY and restart the API.
  3. Admin → Settings → Billing. Paste the publishable key and the secret. They must be from the same Stripe account and the same mode. The panel warns you if they are not.
  4. Developers → Webhooks → Add endpoint.
    • URL: https://your-domain.com/api/v1/webhooks/stripe
    • Event: payment_intent.succeeded
    Copy the signing secret into STRIPE_WEBHOOK_SECRET in apps/api/.env.production, then restart the API container.
  5. Driver payouts use Stripe Connect. The driver app opens Stripe’s hosted onboarding. In Stripe, turn on Connect and set the return URLs to your domain. The admin app already has /stripe/return and /stripe/refresh.

Card payments stay off until Billing has a publishable key and the API has the matching secret. Cash and wallet are separate switches on the same Billing tab.

SMS and WhatsApp

SMS one-time codes

  1. Create a Twilio account and buy a number, or create a Messaging Service.
  2. Set these in apps/api/.env.production (the installer writes them if you answered the prompts): 
    TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_PHONE_NUMBER=
TWILIO_MESSAGING_SERVICE_SID=
    Use either the from-number or the Messaging Service SID. For production, prefer the Messaging Service and leave the from-number empty.
  3. Restart the API. Registration and password reset then send a real code.

WhatsApp booking

A rider can text Ride, Bid, or Parcel instead of using the app. Drivers still use the driver app. Payment on this channel is cash.

  1. In Twilio, open Messaging → Try it out → Send a WhatsApp message, and join the sandbox from your phone.
  2. Set TWILIO_WHATSAPP_FROM to the sandbox number, usually +14155238886.
  3. In Twilio, set the webhook for incoming messages to https://your-domain.com/api/v1/webhooks/whatsapp, method POST.
  4. Admin → Settings → General. Turn on WhatsApp booking. Edit the welcome text if you want.
  5. From a phone that joined the sandbox, send hi. Reply Ride, then a pickup address, then a drop-off, then the class number, then YES.

Leave OPENAI_API_KEY empty to require those keywords. Set it if you want normal sentences mapped onto the same steps. A live business number needs WhatsApp approval in Twilio. Until then, only sandbox members can book.

File uploads

Driver photos and KYC files upload through a presigned URL. Configure Amazon S3 or Cloudinary on the API. The step-by-step S3 policy, CORS, and IAM user are in ryvo-admin/docs/AWS_S3_SETUP.md.

S3 variables in apps/api/.env.production:

AWS_S3_BUCKET=
AWS_REGION=
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=

Cloudinary, if you use it instead of new S3 uploads:

CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=

Restart the API after saving. Keep the bucket private. Admins open documents through a short-lived link. The admin panel does not need the bucket to be public.

Customer app

Build this after the API health check succeeds in a browser.

  1. Install Flutter and run flutter doctor. Fix anything it marks as required for Android or iOS.
  2. Connect Firebase for this app. See Firebase push.
  3. From the project root: 
    cp scripts/whitelabel.env.example scripts/whitelabel.env
  4. Edit scripts/whitelabel.env: 
    API_BASE_URL=https://your-domain.com/api/v1
WS_BASE_URL=https://your-domain.com
MAPS_API_KEY=your-maps-key
APP_NAME=Ryvo
ANDROID_APPLICATION_ID=com.yourcompany.ryvo.customer
IOS_BUNDLE_ID=com.yourcompany.ryvo.customer
  5. Print the build commands: 
    bash scripts/configure-apps.sh
  6. Run the customer command it prints. A release APK looks like this, with your own URL and key: 
    cd ryvo-customer
flutter pub get
flutter build apk --release \
  --dart-define=API_BASE_URL=https://your-domain.com/api/v1 \
  --dart-define=WS_BASE_URL=https://your-domain.com \
  --dart-define=MAPS_API_KEY=your-maps-key
  7. iOS, on a Mac, from ryvo-customer: 
    flutter build ipa --release \
  --dart-define=API_BASE_URL=https://your-domain.com/api/v1 \
  --dart-define=WS_BASE_URL=https://your-domain.com \
  --dart-define=MAPS_API_KEY=your-maps-key

A debug run on the Android emulator:

cd ryvo-customer
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000/api/v1 \
  --dart-define=WS_BASE_URL=http://10.0.2.2:4000 \
  --dart-define=MAPS_API_KEY=your-maps-key

The Maps key in AndroidManifest.xml and Info.plist, and the API fallback in lib/core/constants/app_constants.dart, are xxxxxxxx. Replace them, or pass --dart-define, before you ship. A build that omits --dart-define uses that fallback.

Release Android builds need a keystore. Create ryvo-customer/android/key.properties (this file stays out of git):

storePassword=your-store-password
keyPassword=your-key-password
keyAlias=upload
storeFile=/absolute/path/to/upload-keystore.jks

Create the keystore with keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload. Keep the file. You cannot update the Play listing without it.

Driver app

Repeat the customer steps from ryvo-driver. scripts/configure-apps.sh prints the driver command as well. Use a different Android application id and iOS bundle id from the customer app. Both apps talk to the same API.

The driver release signing file is ryvo-driver/android/key.properties, with its own keystore. Do not reuse the customer upload key if the Play listings are separate apps.

A driver who just registered cannot go online until Verification in the admin panel is approved, and until any required agreement on the Agreements screen is accepted.

Day-to-day use

A rider

  1. Install the customer app. Choose the country, enter the phone number, and create a password. Enter the SMS code.
  2. Allow location. Set pickup and drop-off, or pick a saved place.
  3. Choose Ride, Bid, or Parcel. Ride uses the quoted fare. Bid lets the rider offer a fare inside the limits you set. Parcel asks for the receiver and the size.
  4. Pick a vehicle class and confirm. The app searches for a driver.
  5. When a driver accepts, the map follows them. Chat is available during the trip. Share the trip from the tracking screen if you need someone else to watch it.
  6. Pay by the method that is enabled: card, wallet, or cash. Rate the driver. The receipt stays under invoices.

A driver

  1. Install the driver app and register.
  2. Accept the driver agreement.
  3. Photograph the identity document, driving licence, vehicle, and insurance.
  4. Wait until staff approve the documents under Verification. The app stays on the pending screen until then.
  5. Go online. Accept or decline each offer before it expires.
  6. Navigate to the pickup, mark arrived, start the trip, and complete it.
  7. Earnings shows the fare, the platform fee, and the net amount. Add a bank account or finish Stripe onboarding, then withdraw.

Staff, each morning

  1. Open Verification and clear the pending queue. A pending driver is an idle driver.
  2. Open the live map and confirm drivers are inside the coverage area.
  3. Open Payouts and pay requests that match the driver’s balance.
  4. Open Tickets and answer anything opened overnight.

Staff, when you launch a city

  1. Countries: enable the countries you operate in.
  2. Ride types and fare rules: set prices in your currency.
  3. Coverage: draw the area drivers are allowed to serve.
  4. Settings: currency, commission or subscription, payment methods.
  5. Legal: replace the terms and privacy text with text your counsel has approved. The public pages are /landing-page/terms and /landing-page/privacy-policy.
  6. Create one real rider and one real driver and complete a cash trip before you turn on live card payments.

Updating

On a server that was installed from git:

bash ryvo-admin/docker/redeploy.sh

That pulls, rebuilds, and restarts. Your .env.production, Firebase JSON, and database volume stay in place. Take a database dump first:

docker exec ryvo-postgres pg_dump -U ryvo ryvo > ryvo-$(date +%F).sql

Ship a new mobile build when the API contract changes. Store the same --dart-define values you used the first time. Raise version in each pubspec.yaml before you upload to Play or the App Store. Play needs a higher version code. The +5 in 1.0.0+5 is that number.

FAQ

The installer finished, but the domain does not load.

The stack is on port 4180 of the server, not on the public internet. Finish Public HTTPS. From the server, curl -fsS http://127.0.0.1:4180/api/v1/health should succeed before Nginx will.

Admin login says invalid credentials.

Use the phone you typed into the installer, with the country code, and password 123456. Local installs use +10000000000 / 123456 after npm run db:seed. Check the API log for the line that starts with Super admin:.

The map is grey or blank.

The Maps key is missing, the required API is not enabled, or billing is not on in Google Cloud. The native map uses the manifest and Info.plist keys. The admin live map uses the key saved under Settings → Integrations.

The app opens and shows another company’s data.

The build used the fallback API URL. Rebuild with --dart-define=API_BASE_URL=https://your-domain.com/api/v1 and change the fallback in app_constants.dart.

Registration never gets a code.

On a production server, Twilio must be set and the API restarted. In local development, the API prints the code in its terminal, and 123456 is also accepted.

A driver is online in the app but never receives trips.

Approve verification, confirm the driver is inside the matching radius of the pickup, and confirm the ride type is enabled. Matching radius is under Settings → General.

Card payment fails immediately.

The publishable key and the secret key are from different Stripe accounts, or one is test and one is live. Billing shows that mismatch. Also confirm payment_intent.succeeded is sent to the webhook.

Uploads fail for KYC.

S3 CORS must allow PUT, and the IAM user needs s3:PutObject and s3:GetObject on that bucket. See ryvo-admin/docs/AWS_S3_SETUP.md.
